# 3D (`thistle::three`)

A real 3D renderer: meshes on the GPU, a lit shader, models from Blender (glTF) or anything that exports OBJ, point and spot lights, sun shadows, a sky, fog, particles, instancing, terrain, block worlds, and a built-in character controller that walks on all of it. Everything is in `namespace thistle::three`, next to the 2D API and not tangled with it. `using namespace thistle; using namespace thistle::three;` together is safe.

It's the same idea as the 2D API: you say what to draw every frame, and it's drawn. Nothing stays in the world unless you draw it again next frame.

```cpp
#include <thistle.hpp>
using namespace thistle;
using namespace thistle::three;

int main() {
    App app{{.title = "My 3D Game", .width = 1280, .height = 720}};

    World world;                                   // sun, sky, fog: settings that stay
    Camera camera;
    FlyCamera fly;                                 // click to capture the mouse, WASD to fly
    const Model duck = load_model("assets/Duck.glb");

    app.update([&](Frame f) {
        fly.update(camera, f);
        world.box({0, -0.05f, 0}, {20, 0.1f, 20}, rgb(0.4f, 0.6f, 0.35f));  // ground
        world.draw(duck, {0, 0, 0});
        world.sphere({3, 1, 0}, 0.5f, coral);
        world.render(f, camera);                   // draw it all, once
        f.text("hello", {20, 20}, {.size = 24, .color = white});  // 2D after render() goes on top
    });
    return app.run();
}
```

Conventions, the same as glTF and OpenGL: right-handed, +Y is up, a camera with no rotation looks down -Z, angles are radians (`radians(90.0f)` converts), and 1 unit is 1 meter.

The quickest way to see all of this working is a template: `thistle new mygame --template fps` (or `third-person`, or `voxel`) makes a complete playable game in 200-350 lines you can read. See [cli.md](cli.md).

> Not to be confused with the older "minor 3D" calls on `Frame` (`f.cube()`, `f.camera3d()`, `load_mesh()`; see [drawing.md](drawing.md)). Those are sokol_gl's legacy immediate mode with one fixed light, and they still work. Use this for anything new.

## `World`: set it up once, draw every frame

A `World` holds settings that stay until you change them (`sun`, `sky`, `fog`, `ambient`) and collects what you draw each frame. `render(f, camera)` draws that frame's objects, lights and particles, then forgets them.

- **Where it lands among the 2D.** `render()` happens at that point in the frame's 2D drawing order. 2D drawn after it is on top (the HUD). 2D drawn before it is behind, which means hidden by the sky unless you set `world.sky.visible = false`.
- **More than one view.** `render(f, camera, viewport)` draws into a rectangle of the window (pixels, top-left origin). Call it twice with two cameras for split-screen, or once more for a minimap.
- **Post effects** (`set_post_effect()`) apply to the 3D too.

## Cameras

`Camera` is a position, a rotation, and a lens: `fov` (vertical, radians), `near_z`/`far_z`, or `orthographic` with `ortho_height`. `camera.look_at(target)` points it. `forward()`, `right()`, `up()` give its directions.

Three controllers read input and move a camera. Call one's `update(camera, f)` once per frame. They're plain structs, so set any field whenever you like, e.g. turn `MouseLook::yaw` to face a spawn point.

- **`MouseLook`**: first-person. Clicking the window captures the mouse and Esc lets go (or set `capture_mouse = false` to turn only while the right button is held). The gamepad's right stick turns too. `move_input(f)` turns WASD / arrows / the left stick into a flat world direction relative to where you face, ready for a `CharacterController`.
- **`FlyCamera`**: noclip. MouseLook plus WASD, E/Space up, Q/Ctrl down, Shift for speed. The debug camera.
- **`OrbitCamera`**: circles a `target`. Right-drag orbits, the wheel zooms, middle-drag pans. For a third-person game, set `target` to the player every frame and turn on `capture_mouse`. `apply(camera)` places the camera without reading input, for when you want to adjust it yourself (the third-person template pulls it in front of walls).

`camera.screen_ray(f.mouse(), f)` is the ray under the mouse, for picking (see [Raycasts](#raycasts-and-picking)). `camera.world_to_screen(point, f, out)` is where a 3D point lands on screen, for nameplates and health bars. It returns false for points behind the camera.

## Shapes, meshes, materials

The quickest things to draw need no setup:

```cpp
world.box({0, 0.5f, 0}, {1, 1, 1}, coral);          // center, size
world.sphere({2, 1, 0}, 0.5f, white);
world.cylinder({-2, 1, 0}, 0.5f, 2.0f, rgb(0.3f, 0.5f, 0.9f));
world.cone({4, 0.5f, 0}, 0.5f, 1.0f, rgb(0.8f, 0.4f, 0.8f));
world.plane({0, 0, 0}, {10, 10}, rgb(0.5f, 0.5f, 0.5f));  // flat on the ground, facing up
world.box(Transform{pos, quat::euler(0, radians(45), 0), {2, 1, 1}}, color);  // turned and scaled
```

For anything else, build a `MeshData` (vertices and triangles, counter-clockwise from the front) and turn it into a `Model` with `make_model(mesh, material)`. `box_mesh()`, `sphere_mesh()`, `cylinder_mesh()`, `cone_mesh()`, `capsule_mesh()` and `plane_mesh()` are starting points. `append()` merges meshes, `set_color()` paints vertices, and `make_flat()` gives the faceted low-poly look (a low-resolution `sphere_mesh()` plus `make_flat()` is a rock).

A `Material` is: `color`, an optional `texture` (any `load_texture()`), `emissive` (+ `emissive_texture`, for glow maps), `specular` and `shininess` (the highlight), `unlit`, `double_sided`, `alpha` (`Opaque`, `Cutout` for leaves and fences, `Blend` for glass and water, drawn last and sorted back to front), `uv_scale` for tiling, `filter` (`Nearest` for crisp pixel art), and `casts_shadow`. Vertex colors multiply in, which is how vertex-colored low-poly models get their colors.

Lighting is Blinn-Phong in linear space: a diffuse and a highlight per light, plus the sky's colors as ambient. It isn't physically based. There are no normal maps and no metal/roughness maps (a glTF's roughness value is mapped onto the highlight's size, its maps are ignored).

## Models

```cpp
const Model ship = load_model("assets/ship.glb");   // .glb, .gltf or .obj (+ its .mtl)
world.draw(ship, Transform{pos, rotation});          // as many times per frame as you like
world.draw(ship, pos, rgb(1, 0.5f, 0.5f));          // tinted
```

- **glTF / GLB** (what to export from Blender): the node hierarchy, base color (factor and texture: external, embedded, or a data URI), emissive (with strength), alpha modes, double-sided, unlit, nearest-filtered samplers, texture scale, vertex colors, and skins and animations (see [animation.md](animation.md)).
- **OBJ**: one part per material, quads and polygons split into triangles, the `v x y z r g b` vertex-color extension, and from the `.mtl`: diffuse color and texture, glow color and texture, highlight, transparency.
- Textures are found relative to the model file.
- `load_model_data()` gives you the parsed file (parts, each a mesh, a material and a placement) to change before `make_model()`: recolor a part, merge parts, bake several into one.
- `set_model_material(model, material, part)` changes a loaded model's look. `world.draw(model, transform, material)` overrides it for one draw.
- A file that can't be read logs a warning and gives an invalid `Model`, which draws nothing.

**`load_model()` doesn't cache.** Every call reads the file and uploads it again. Load each model once, at startup, and keep the `Model`: it's a small handle, fine to copy. (`Scene3D` does share models by path, see [scene3d.md](scene3d.md).) `unload_model()` frees one.

## Lights, sky, fog, shadows

```cpp
world.sun.direction = {-0.4f, -1.0f, -0.3f};        // the way the light travels
world.sun.shadow_distance = 40.0f;                   // smaller = sharper shadows up close
world.fog.enabled = true;
world.fog.start = 30; world.fog.end = 120;
// every frame, for every light that's on:
world.light(PointLight{.position = lamp, .color = rgb(1, 0.8f, 0.5f), .range = 8});
world.light(SpotLight{.position = p, .direction = d, .angle = radians(25)});
```

- **The sun** lights everything from one direction and casts the shadows: one shadow map, fitted around the camera out to `shadow_distance` meters and faded out at the edge, with soft (3×3 filtered) edges. `Cutout` materials cast shaped shadows (leaf cards cast leaves). `Blend` ones never cast.
- **Point and spot lights** (`world.light()`, every frame like `draw()`): up to 16 per `render()`. Past that, the ones nearest the camera win, off-screen ones dropped first. Their light falls to exactly zero at `range`. **They don't cast shadows**: only the sun does.
- **The sky** is a gradient (`top`, `horizon`, `ground`) with a sun disc, or a cube map: `world.sky.skybox = load_skybox(right, left, top, bottom, front, back)`. Its colors also light the scene: surfaces facing up pick up the top color and facing down the ground color, scaled by `world.ambient`. So shadowed sides are tinted by the sky instead of going black, and a sunset skybox tints everything.
- **Fog** fades things into a color between `start` and `end` meters. With `match_sky` (the default) it takes the horizon color, so distant things melt into the sky. It's also how an endless world hides where it stops.
- **Emissive** materials glow at full brightness in the dark. They don't light anything around them: add a point light for that.

## Many copies: `draw_many`

```cpp
std::vector<Transform> trees = ...;                  // 10,000 of them
world.draw_many(tree, trees);                        // one draw call per part of the model
world.draw_many(tree, trees, tints);                 // each with its own tint
```

A forest, grass, rubble, a crowd: GPU instancing, shadows included. The copies are culled as one group, so split a big spread into a few groups by area if most of it is usually off-screen. `forest_demo` draws 10,000 two-part trees and 1,500 rocks in 9 draw calls.

## Billboards and particles

`world.billboard(Billboard{...})` is a picture in the world that turns to face the camera: far-away trees, a Doom-style enemy, an objective marker. It takes a sprite-sheet frame like the 2D API, can stay `upright` (only turn around the vertical axis), and can be `additive` (glowing).

```cpp
ParticleSystem fire;
fire.settings.start_color = rgb(1, 0.6f, 0.2f);
fire.settings.additive = true;
// every frame:
fire.emit(campfire, 3);
fire.update(f.dt);
world.draw(fire);
```

Settings cover start/end color and size, lifetime (with jitter), a starting velocity plus a random `spread`, gravity, drag, spin, and a texture (none = a soft dot). `emit(pos, n, other_settings)` fires a one-off burst in a different style from the same system (sparks from the fire). `particles()` gives read-only access. Particles are unlit and fogged.

## Terrain and noise

```cpp
Terrain land(256, 256, 1.0f);                         // cells, cell size in meters
land.generate([](float x, float z) { return 12.0f * fbm(x * 0.01f, z * 0.01f); });
// every frame:
world.draw(land);
```

A heightmap drawn as low-poly triangles colored by height and slope (sand, grass, rock, snow, or your own `colorize` function), split into tiles that are culled separately. `height_at(x, z)` is the exact height on the drawn triangles, for dropping trees onto it. `set_height()` edits it (it rebuilds on the next draw). `collision.add(land)` makes it walkable.

The noise functions (`perlin`, `perlin3`, `fbm`, `fbm3`, `ridged`) are seeded and give the same values on every machine, so every player of a multiplayer game generates the same world.

For block worlds (Minecraft, Teardown, MagicaVoxel), see [voxels.md](voxels.md).

## Raycasts and picking

```cpp
const Ray ray = camera.screen_ray(f.mouse(), f);     // or Ray{camera.position, camera.forward()} for a crosshair
if (RaycastHit hit = raycast(ray, crate, crate_transform)) {
    // hit.distance, hit.point, hit.normal
}
```

`raycast()` works against a box (`Bounds`), a sphere, a plane, a triangle, or a whole model at a transform (every triangle, exactly, after a bounds check). `CollisionWorld::raycast()` casts against everything in one (below), and `VoxelWorld::raycast()` against blocks. Keep the ray's direction normalized: distances are in its units.

## Walking around: `CollisionWorld` and `CharacterController`

Built in, no physics library needed. A `CollisionWorld` is the static stuff: models (their triangles), terrain, block worlds (read live, so a broken block stops blocking at once) and boxes. A `CharacterController` is an upright box that walks on it: slides along walls, lands on floors, climbs steps (`step_height`, 0.55 m), treats slopes steeper than `max_slope` as walls, and jumps, with coyote time and a jump buffer.

```cpp
CollisionWorld level;
level.add(level_model, level_transform);
level.add(terrain);
CharacterController player;
player.position = {0, 5, 0};                          // the middle of its feet
// every frame:
look.update(camera, f);
player.update(level, look.move_input(f), f.key_pressed(Key::Space), f.dt);
camera.position = player.eye();
```

A level from the editor fills one with `scene.add_colliders(level)` ([scene3d.md](scene3d.md)). For things that tumble, stack and get knocked over, that's rigid-body physics: the opt-in `Physics3D` on Jolt ([physics3d.md](physics3d.md)).

## Debug drawing

`world.line(a, b, color)`, `wire_box()`, `wire_sphere()` and `grid()` draw 1-pixel lines, hidden behind solid things or with `on_top = true` drawn through them. `render_stats()` gives the previous frame's draw calls, triangles and culled parts. With the debug UI turned on ([ui-and-scenes.md](ui-and-scenes.md)), `debug_stats_window()` shows them along with a frame-time graph.

## Things to know

- **Construct the `App` first.** Textures (and so textured materials, atlases, skyboxes) can't be created before it exists: it logs a warning. Models can be loaded any time after that, before `run()` too.
- **Everything is per frame.** `draw()`, `light()`, `billboard()`: draw it every frame or it's gone. Settings (`sun`, `sky`, `fog`, `ambient`) are what stays.
- **No anti-aliasing.** The window is created without MSAA, so edges are jagged.
- **No HiDPI.** The window doesn't ask for a high-DPI framebuffer, so on a Retina/HiDPI screen everything (2D too) renders at the lower resolution and is scaled up. This is the engine's existing setting, not something 3D changed. It's untested either way.
- **Shadows come from the sun only**, one map for the whole view: fine for an outdoor level out to a few dozen meters. Wide views with sharp shadows far away aren't what it's for.
- **Performance** was only measured on a software renderer (below), which is far slower than any GPU, so the numbers are only good for comparing things with each other. `forest_demo` (434,000 triangles, 9 draw calls) ran at about 10 fps on it, and `animation_demo`'s 24 skinned robots at about 50 fps.

## What's been verified

Every feature was run and looked at before it was called done, but **on Linux under Xvfb with Mesa's llvmpipe**: a software OpenGL renderer in a container, not a GPU driver. That proves the shaders, the math and the image orientation on the GL backend. It doesn't prove what a real GPU driver does.

- **Seen rendered (Xvfb + llvmpipe, screenshots):**
  - lit shapes and a see-through sphere, with 2D before and after `render()` and a split-screen viewport (`three_smoketest`)
  - models: the Khronos samples Duck, BoxVertexColors, CesiumMan, Lantern (the glow map), AlphaBlendModeTest and Fox (`model_viewer`)
  - point and spot lights by day and by night, fog, the sun disc, each skybox face checked for the right way round (`lights_smoketest`)
  - soft sun shadows with a low sun, without acne
  - instancing: 10,000 trees (`forest_demo`)
  - particles and billboards: a campfire with sparks and smoke, sprite trees, a sprite-sheet frame
  - terrain with 3,000 instanced trees (`terrain_demo`) and a streamed endless block world (`endless_demo`)
  - mouse picking, fly and orbit cameras, mouse capture, driven with xdotool
  - skinned characters walking and running (`animation_demo`)
  - the three templates played through (see [scene3d.md](scene3d.md#whats-been-verified))
- **Tested headless in ctest (every CI run, on macOS, Windows and Linux):**
  - `math3d_smoketest`: rotations, projection, inverses, rays, frustum
  - `mesh3d_smoketest`: winding, normals and bounds of every shape
  - `model_smoketest`: OBJ+MTL, embedded glTF and GLB, field by field
  - `particles_smoketest`: including flight matching the exact 60 Hz answer
  - `terrain_smoketest`: noise and terrain, a character landing on it
  - `character_smoketest`: landing, walls, slides, steps, slopes, jumping, simulated at 60 Hz
  - `animation_smoketest`: a skinned glTF written by the test, bends checked in degrees
  - `audio3d_smoketest`: 3D sound calls are safe with no audio device (how it sounds was checked by recording real output, see [input-and-audio.md](input-and-audio.md#3d-sound-thistlethree))
- **Shaders:** `tools/shaders/build_shaders.py --check` compiles every stage's generated HLSL (D3D11) and GLSL ES (Android/web) through glslang. Metal can't be checked off a Mac.
- **CI** compiles everything, the examples and templates included, with MSVC on Windows, Apple Clang on macOS and GCC on Linux. It has no GPU, so it doesn't draw anything.
- **Not yet seen on screen: Metal (macOS/iOS), D3D11 (Windows), any real GPU, Android, the web.** The backend differences the code handles (clip-space depth, shadow-map texture origin, cube-map handedness) are reasoned from the specs and the sokol source, not yet run. The first person to run a template on a Mac or a Windows PC is the first real test of those. If something is upside down, mirrored or has no shadows there, that's where to look.
